Roadmap#

Chapter 24 of 24Source: docs/roadmap.md

Guiding rule: the framework only grows features that a real show demanded. (This is how the core was born — every module here drove an actual performance before it was generalized.)

v0.x — the chassis (now)#

  • four layers: input (midi/audio/chord/pose) → mapping → world → output
  • timeline with scenes, negative standby time, cue hook
  • director's console + performance mode
  • backstage monitor (zero-dep WS relay, LAN devices)
  • OSC bridge; MIDI out with observable throat + panic
  • tests for all pure logic (chord, timeline, mapping, params)
  • mapping profile import/export UI (JSON file, drag-and-drop, ?map=<url>, remembered per world)
  • example: audio-reactive world driven by a live instrument (mic) — 06-cylinder-earth
  • drum machine with analyzer-shaped signals (@openav/drums)
  • on-screen MIDI controllers that mirror real hardware (@openav/midi, example 09)
  • a documentation site: openaudiovisual.com/docs
  • oav-p5: one line for any p5.js sketch, with controllers, a phone, the microphone, sound, a drum machine you can write as one line of rhythm, bars and cues, and video recording; versioned on its own (changelog)
  • one line of rhythm, TidalCycles/Strudel-style mini-notation (@openav/pattern)
  • values over time as TouchDesigner's CHOPs shape them: lag, envelope, speed, spring, trail (@openav/chop)
  • next to Strudel: what a program plays into OAV Virtual MIDI, an external MIDI clock, and link=<room> across tabs and computers (With Strudel)
  • the whole show's automation as curves on the desk, curves written per segment of the score, automation saved and loaded as JSON, a timeline anchored to the wall clock (Show control)
  • a route that trims the timeline or waits for pickup, and gives the param back (@openav/mapping)
  • several pages, one show: a leader and its followers, in one browser or across machines (@openav/sync)
  • a version for the whole framework and an address that never changes; a show in one file, with no clone (Pin a version)
  • Made with: the works that run on it, each added by the person who made it
  • the stage on a projector or a second screen: an output window, four-corner correction, crops for projectors side by side, blackout and brightness as params, and a clean address for OBS and TouchDesigner (@openav/output, Projection and video out)
  • several screens lying on a table as one canvas, placed by one photo, on one shared clock (@openav/tile, Several screens, one canvas); on a real table with real phones: still to be tried
  • a wall of several outputs from one layout file: test patterns, a vendor chart and the output mapping read the same data; corners, mesh, feather and masks by hand; the Gray-code frames (@openav/align, Projector and LED alignment); on a real projector: still to be tried
  • automatic alignment with a camera: capture, decode, the camera ↔ projector correspondence, a solved mesh, a measured blend (what is not built yet)

So that nobody rebuilds this layer#

The aim is that a performance on the web starts from here the way a website starts from a server someone else already runs. A layer earns that when people can build on it without asking. What that takes, and where each part stands:

partthere nownext
a version to depend on0.9.0, a pinned address, a changelog1.0: the World contract, the signal names and the profile format stop changing without a major version
a way in without the repositoryone file and one importthe same for a controller page and a phone remote
formats others can readcontroller profiles with a JSON Schema, exports to QLC+ and Mixxx, map files, the scoreeach format with its own version number; the profile format as something other tools adopt
controllers you can trust55 profiles, every number with its source, a page that checks a unit by handthe first profiles checked on hardware; more from the people who own them
recipes for the roomOSC to TouchDesigner, lights and spatial audio; the picture on a projector, and written recipes for OBS and TouchDesigner with a venue checklist (Projection and video out)the OBS and TouchDesigner recipes run in each app; a kiosk iPad
proofthe shows it came fromworks by other people on Made with
a place to askissues, a form to ask for a controller, a form to add a workanswers within days

v1.x — the show grows#

  • Audience-device input — classic controller shipped (@openav/relay, @openav/surface, @openav/remote): a zero-dep room server, phone/{id}/* sensors, a TouchOSC-style widget set, layout JSON, autoSurface(params), feedback to the phone. Next:
    • QR code on the join card (@openav/remote/qr, a ~150-line zero-dep encoder) — and on static hosts the show uses the public relay with a random room, so the examples on openaudiovisual.com take phones too
    • experimental surfaces: gesture/physics widgets, shared multi-user surfaces, audience-mode (many phones → aggregate signals like crowd/tilt/mean)
    • mic as a phone sensor; per-device profiles; layout editor / import-export UI
  • Score & Director — shipped (@openav/score): cuts as segment lengths, derived versions, cues, hold, segment modules that fail alone, the prompter's acts, score → MIDI markers. Next:
    • MIDI clock in: MidiClock (@openav/midi) follows start, stop and song position, and oav-p5's drum machine and drumPhase follow it (0.7)
    • the score on an external clock, and clock and transport out, so a DAW can be the master clock of the score, or follow it
    • a clocks table in the cut, only if a show needs engines on two different time lines (see Score & Director)
    • a score editor on the desk: drag a segment's length, see every cue move
  • Signal recording & replay — MIDI takes shipped (@openav/record: TakeRecorder, TakePlayer, .mid in and out; EventLog already records any signal beside a video). Next: replay the full signal stream (hands, body, audio analysis) into any world. Rehearse without the performer; archive the gesture, not just the video.
  • npm publish of @openav/*, once 1.0 says what stays put (until then: pin a version), and docs pages that are themselves performable with the framework.
  • WebGPU world adapter as WebGPU compute matures for particle/agent worlds.

v2.x — the stage widens#

  • The picture into video pipelines: first as recipes with tools that exist (OBS Browser Source with NDI out, TouchDesigner's Web Render TOP). Recipes written (Projection and video out), with a clean address (?output) and an output window to feed them; what each app does with the page is still to be run in the app. A gateway of our own (headless browser → NDI) only if a show needs what those cannot do.
  • Distributed performance: multi-browser signal sync over WebRTC data channels — several machines, one signal space, geographically split ensembles. The clock half shipped: several pages perform one show, the followers chasing a leader's timeline over a BroadcastChannel or the room relay (@openav/sync). Signals still stay on the page that took them.
  • Agent performers: LLM-driven agents subscribing to signals and writing params — improvising alongside humans (lineage: The Last Input's autonomous city agents).

Non-goals#

  • a node-based visual editor (cables.gl does this well; we are a library)
  • a synthesis toolkit of our own (Tone.js is the neighbor: @openav/sound wraps it behind a small engine contract, and audio.input() accepts its nodes)
  • being a platform: your show is your repo, not an account on our server
