Package reference#

Chapter 20 of 24Source: docs/packages.md

Thirty-four packages live in packages/<name>/. Each is plain ES modules with no dependencies; in a page you import them as @openav/<name> through an import map (copy the one in examples/01-hello-particles/index.html). Nothing is on npm yet.

layerpackages
L1 inputmidi · audio · chord · pose · leap · keys · drums
L2 mappingmapping · chop
L3 worldstage · world-webtoe
L4 outputsound · osc · out · dmx · output · align · record · fab (and MIDI out in midi)
spinestimeline · score · pattern · console · monitor · sync
phonesrelay · surface · remote · tile
gluecore · show · devices · mcp

Subpath entries (@openav/remote/host, @openav/relay/server, @openav/surface/layout, @openav/surface/auto) need their own import-map line in a browser, for example "@openav/remote/host": "../../packages/remote/host.js?v=cedb93fa".

@openav/show#

Glue · createShow(options): one call that assembles a whole show around a world and returns every part. Options, modules and the return value are in Show control; loop, monitor and console (the desk's keys) choose who drives the frames, where the backstage feed goes and which keys run the desk; sync makes the page one of several that perform the same show (leader or follower, @openav/sync). The same page at ?output is a clean output: the stage alone on black, no desk (@openav/output).

js
import { createShow } from '@openav/show';
const show = await createShow({ world, modules: { keys: { base: 48 }, sound: true } });

@openav/chop#

L2 mapping · values over time, the way TouchDesigner's CHOPs shape them: Lag, Trigger (envelope), Speed, Spring, Trail, Slope, Count. Pure logic, no clock of its own: every step is told the seconds that went by and is solved exactly over them, so 30 fps and 144 fps draw the same curve. What the parameters mean follows Derivative's TouchDesigner documentation; the code is OAV's own. In a p5 sketch, oav-p5 gives these one call each: p5 one line.

exportsignature
approachapproach(current, target, seconds, dt) → one step of a one-pole lag; seconds = time to 63% of a change (the smooth of @openav/mapping, which steps with it)
Lagnew Lag({ up = 0.1, down = up }) · step(input, dt, up?, down?) → output · reset(v?): up while rising, down while falling (Lag CHOP's Lag 1 / Lag 2), in TouchDesigner's seconds (about 90% of a change)
envelopeenvelope(times, t, attack = 0.01, decay = 0.3, peak = 1) → the Trigger CHOP's level at t for events at times (seconds, oldest first): a straight attack (0 → peak), then 0 after exactly decay; a retrigger starts where it is · envelopeStage(elapsed, attack, decay, from, peak)
Speednew Speed() · step(rate, dt) → position: rate per second
Springnew Spring({ stiffness = 100, damping = 6 }) · step(target, dt) → position (velocity alongside): a mass on a spring pulled to the input, solved exactly · springStep(x, v, target, k, c, dt) → [x, v]
Trailnew Trail({ seconds = 2, rate = 60 }) · step(value, dt) → the last seconds, 60 values a second plus the newest, oldest first, fixed length
Slopenew Slope() · step(value, dt) → change per second
Countnew Count({ threshold = 0.5 }) · step(on, limit = 0) → times it turned on, looped to 0 … limit − 1 with a limit · wrapCount(total, limit)
TD_LAG_RATIO, DEFAULTSMath.LN10: two kinds of seconds. Lag and lag() take TouchDesigner's Lag CHOP seconds (about the time to follow 90% of a change), so lag(x, 0.1) moves like a Lag CHOP set to 0.1; underneath, Lag divides by TD_LAG_RATIO (2.3) to get its time constant. approach(…, seconds) takes that time constant itself (63% of a change, what @openav/mapping's smooth always meant); the defaults above
js
import { Lag, envelope } from '@openav/chop';
const vu = new Lag({ up: 0.03, down: 0.4 });       // opens at once, closes slowly
// every frame: r = 50 + vu.step(level, dt) * 300; pump = envelope(kickTimes, now, 0.01, 0.3);

@openav/dmx#

L4 output (lighting) · DMX from a page, as pure logic: fixture profiles (open-audiovisual/fixture@1), a patch that turns properties (dimmer, color, pan, tilt, strobe, zoom, 0..1) into each light's bytes, and an engine that renders every light at any moment as a function of time: base scenes → cues with fades → chases on beats → effects → live values → per-fixture limits → grand master → blackout. Safety is on by default, and the flash cap (3 a second) is held per fixture, twice: the engine slows the effects and chases that flash one fixture until their rates there add up to at most the cap (state(t).slowed), and every dmxTransport() puts each frame through a flash guard that holds what a fixture really emits, live values included (rises are rationed, falls always pass; { flashGuard: false } to switch it off, and the monitor then says so). A strobe channel whose profile gives Hz is held to the cap, one with no Hz stays open; render(t, { beat }) needs bpm with it, since the cap reads the tempo; control channels (reset, lamp, built-in programs) are written only by control(); blackout leaves pan and tilt where they are. The bytes of Art-Net, sACN and the Enttec DMX USB Pro come out of pure encoders; dmxTransport() sends what changed each frame (to memory, through the out-bridge, or by Web Serial), dmxParams() makes the engine's control points params, and mountDmxMonitor() shows the rig on the page. Nothing has been tried on a real fixture, node or interface. The chapter is DMX lighting.

@openav/output#

L4 output (picture) · the stage on a projector, a second screen, OBS or TouchDesigner. An output window that mirrors the stage's canvas (captureStream() into a <video>: one render, the same frames) or opens the same page again at its clean address as a sync follower; fullscreen on a chosen screen where the Window Management API allows it (asked only from a click in the output window); four-corner correction as one CSS matrix3d homography, with flip, a quarter turn, a black border and a soft edge, edited with four handles and a test pattern and saved per output name; crops of one canvas for projectors side by side (no edge blending); output/<name>/blackout and output/<name>/brightness as params. Any createShow() page at ?output is a clean output (&follow=oav-output to follow, &play to start). The chapter is Projection and video out.
