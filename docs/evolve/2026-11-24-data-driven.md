### 2.5 量不到的（這本身是發現）

- **站上只有瀏覽事件**。GA 事件表只有 page_view、session_start、first_visit、user_engagement 四種，沒有任何點擊、複製、播放事件。有沒有人複製那一行載入碼、有沒有人點去 GitHub、有沒有人彈了虛擬控制器，全部不知道。

## 三、三個最大的流失點

**1. 進來之後沒有下一步，也量不到。**
控制器頁是最大的入口（一半的搜尋曝光、幾乎全部的 AI 引薦），但從控制器頁出去的連結只有 GitHub、原廠文件與相鄰的控制器。一個搜「APC mini mk2 MIDI map」進來的人，查完就走，沒有被告知「這台可以一行接上 p5.js」。速查表（上課的人）、範例頁同樣沒有往下一步的出口。再加上沒有事件，連流失在哪一步都看不到。

**2. 手機。**
手機佔三分之一的工作階段（287），互動率 23%、平均停留 34 秒；桌機是 44%、188 秒。社群貼文的點擊多半在手機上（社群手機 59 個工作階段、平均 18 秒），控制器總表在手機上有 82 個工作階段、只有 23 個有互動。這個框架要桌機、Chrome、最好有一台控制器，手機訪客看到的卻是同一份給桌機的頁面，沒有「先看一段」「把連結寄到電腦」這種適合手機的路。

**3. 控制器以外的內容在搜尋裡幾乎不存在。**
- 文件是一張 52 萬位元組的單頁，參考頁是一張 313 萬位元組的單頁。每一章沒有自己的網址、標題與描述，所以 Google 只能拿整本手冊去配查詢字，配到的是「node av」「ahora no suena nada」這種不相干的字，351 次曝光只有 5 次點擊。
- 27 個範例頁加起來 116 次曝光。
- `/p5/` 是對最大一群潛在使用者（p5.js、OpenProcessing）的主打，63 次曝光。p5.js 官方 libraries 的投稿（PR #1657）11/18 送出後還沒有人審。
- 英文搜尋曝光多、點擊少（美國 CTR 2.7%）。

## 四、官網怎麼改

### 4.1 先把量測與出口裝上（最便宜、其他每一項都靠它驗收）

- 事件（都不帶個資，只記發生了什麼）：複製載入碼、複製範例程式、點「在 OpenProcessing 開啟」、虛擬控制器被彈、下載匯出檔（QLC+、Mixxx）、站外點擊（GitHub、課程、作品、原廠）、範例開始互動。
- 每一類頁面底下一塊固定的「下一步」：
  - 控制器頁 →「這台接上 p5.js，一行」（帶這台的 id 的現成程式）＋「用它演一個範例」。
  - 速查表、參考頁 → 相關範例、作品登記。
  - 範例頁 → 這個範例用到的章節、同一路線的下一個。
  - 首頁 → 加「誰在教這個」（課程）與「用它做的作品」兩條。**課程連到哪個網址、怎麼稱呼，要你定**（意圖卡：對外句子不替你寫）。
- 把 `llms-full.txt` 從 Google 搜尋結果拿掉（既有待辦 S13，要在 Cloudflare 加一條回應標頭，要你點頭）。

### 4.2 手機的路

- 手機進來時，頁首先給：一段 20 秒內的實際畫面（靜音自動播放）、可以用手指彈的虛擬控制器、「把這頁寄到我的電腦」（複製連結或 QR 反向：電腦開、手機當遙控，`@openav/remote` 已經有）。
- 控制器總表在手機上先給搜尋框與品牌篩選，不要一次載 55 台的圖（現在這頁 31 萬位元組）。

### 4.3 文件拆頁

- 每一章一個網址（`/docs/<章>/`），有自己的 title、描述、上下章連結。`/docs/` 留著當目錄，舊的 `#錨點` 連結自動跳到新頁，不壞任何外部連結。
- 參考頁每個公開名稱一個網址（p5.js 的 reference 就是這樣），總表留著當索引。550 個名稱＝550 個可以被搜到的頁，每頁本來就有可跑的範例。
- 這兩件都只動生成器（`tools/build-docs.mjs`、`tools/build-reference.mjs`），內容來源不變。

### 4.4 範例畫廊

- 每個範例頁加：一段錄好的畫面（`@openav/record` 自己錄）、用到的輸入與套件、三句「你會學到什麼」、可以直接改的程式。現在範例頁的靜態說明很薄，搜尋與手機訪客都看不到它在做什麼。
- 依「我手上有什麼」重排入口：只有鍵盤、有 MIDI 控制器、有鏡頭、有手機、有燈。

### 4.5 `/p5/` 對準 p5.js 使用者會搜的字

- 第 4 堂學員實際卡住的點，每個做成一個找得到的答案：網頁收不到麥克風、插了 MIDI 鍵盤 OpenProcessing 沒反應、買了 MiniLab 3 不會用、想換音色、iPad 與 Safari 沒有 Web MIDI。這些就是別人會搜的句子。

## 五、設備大集合

### 5.1 為什麼數據支持這件事

現有 55 台控制器的頁（27 台手寫＋28 台從 QLC+ 轉入），中英共 110 頁，就帶來全站 49% 的搜尋曝光與幾乎全部的 AI 引薦。沒有為它做過任何推廣。這是目前唯一被數據證明會自己長的東西，把它從 MIDI 控制器擴到所有演出設備是順著走。

### 5.2 做法

**一個總入口，舊網址不動。** `/devices/` 是總表（可依種類、品牌、接法篩選與搜尋）。`/controllers/<id>/` 已經被收錄，原地保留；新種類各有自己的路徑。

| 種類 | 路徑 | 一頁放什麼 | 資料格式 |
|---|---|---|---|
| MIDI 控制器 | `/controllers/<id>/`（現有） | CC 與 note 對照、可以彈的虛擬控制器、SysEx、匯出檔 | 現有 profile |
| DMX 燈具 | `/fixtures/<id>/` | 每個模式的通道表、可以推的虛擬燈、patch 範例 | `fixture@1`（DMX 報告） |
| DMX／LED 介面 | `/devices/<id>/` | 支援的協定、埠、接法、橋接器設定檔 | `device@1` |
| 感測器與鏡頭 | 同上 | 給出哪些訊號、解析度與更新率、在瀏覽器怎麼拿到、常見問題 | `device@1` |
| 音訊介面 | 同上 | 聲道、取樣率、在瀏覽器選到它的方法、迴授與延遲 | `device@1` |
| 投影機、螢幕 | 同上 | 解析度、流明、投射比、接法 | `device@1` |
| 電子零件 | 同上（`@openav/hw` 現有 16 件） | 腳位、電壓電流、接線圖 | 現有零件庫 |

**`device@1`：一個共用的外層。** 每台設備一個 JSON：身分（品牌、型號、別名）、種類、接法（USB、DIN、乙太網路、HDMI、藍牙）、協定資料（依種類指到 profile、fixture 或零件）、設定步驟、常見問題、在 OAV 怎麼用、每個數字的出處、授權、真機驗證紀錄。附 JSON Schema，別的工具可以直接讀。

**真的有用，每頁至少有三樣別處沒有的：**
1. 可以操作的東西（虛擬控制器、虛擬燈、訊號即時表）。
2. 一段貼上就能跑的程式，帶這台的 id。
3. 可以帶走的檔（QLC+、Mixxx、TouchDesigner 用的對照表、橋接器設定）。
沒有這三樣的設備先不上頁。只有規格表的薄頁大量上線，Google 會整批不收，還會拖累現有的頁。

**跟 OAV 串起來：`@openav/devices`。**

```js
import { device } from '@openav/devices';
const apc = await device('akai-apc40-mk2');     // MIDI：推桿、旋鈕已經是有名字的訊號
const par = await device('generic-rgbw', { universe: 1, address: 1 });   // DMX：par.color、par.dimmer
const cam = await device('logitech-mx-brio');   // 鏡頭：幫你選到這顆、給建議的解析度
```

一個入口，依種類交給現有的套件（`@openav/midi`、`@openav/dmx`、`@openav/pose`、`@openav/out`）。全部是新增的 API，現有寫法不變。oav-p5 那一邊（例如一行 `controller('akai-apc40-mk2')`）等套件穩了再開，因為每個公開名稱都要有參考條目與可跑的範例。
