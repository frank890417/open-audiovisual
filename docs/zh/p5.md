# p5.js 一行接上

任何一份 p5.js 草圖（OpenProcessing、p5 編輯器、你自己的網頁）在最前面加一行，就能用 MIDI 控制器、
螢幕上的控制器或手機來彈：

```js
document.head.prepend(Object.assign(document.createElement('script'), { src: 'https://openaudiovisual.com/p5/oav-p5.js' }));
```

在 OpenProcessing 也可以不寫這行，改把網址貼到右側 Libraries 的 **＋**（自訂函式庫）。p5 1.x、2.x 的全域模式都能用，
`setup()` 裡不用呼叫任何東西。
帶著這一行、現在就能彈的草圖：[範例 15](https://openaudiovisual.com/examples/15-p5-one-line/)。

## 像讀滑鼠一樣讀它

```js
function draw() {
  background(knob1 * 255);                 // knob 1, 0..1, like mouseX
  circle(width / 2, height / 2, 50 + knob2 * 300);
}

function notePressed(note, velocity) {     // like keyPressed(): any key, or a pad
  circle(random(width), random(height), velocity * 100);
}
```

| 讀 | 值 |
|---|---|
| `knob1` … `knob8`、`knob(n)` | 0 到 1，編號照控制器上印的順序 |
| `fader1` … `fader8`、`fader(n)` | 0 到 1 |
| `pad1` … `pad16`、`pad(n)` | 按著的時候是力度，放開回到 0 |
| `note`、`velocity` | 最後按的鍵（MIDI 編號）和多用力（0 到 1） |
| `noteIsPressed`、`noteIsDown(60)` | 跟 `keyIsPressed`、`keyIsDown()` 一樣 |

| 寫這個函式 | 什麼時候被叫 |
|---|---|
| `notePressed(note, velocity)`、`noteReleased(note)` | 按下、放開一個鍵（打擊墊也算，除非你寫了 `padPressed`） |
| `knobMoved(n, value)`、`faderMoved(n, value)` | 轉旋鈕、推推桿 |
| `padPressed(n, velocity)`、`padReleased(n)` | 打擊墊按下、放開 |

旋鈕 1 就是你手上那台的旋鈕 1：[控制器設定檔](controllers.md)記著每顆旋鈕送哪個訊息（MiniLab 3 的旋鈕 1 是 CC 74，
LPD8 是 CC 70）。OAV 沒有設定檔的控制器，你先轉的那顆就是 `knob1`，再轉的是 `knob2`。草圖裡自己已經有
`note`、`velocity`、`knob1` 這些名字的話，原本的會留著。

## 搭配 OP Configurator

[OP Configurator 3000](https://github.com/msawired/OPC)（OPC，OpenProcessing 內建）幫變數取名字、定範圍。
頁面上有這一行，控制器就照宣告順序接上這些變數，不用一個一個對應：

```js
OPC.slider('radius', 60, 10, 300);   // knob 1
OPC.slider('speed', 1, 0, 5, 0.1);   // knob 2
OPC.toggle('trails', true);          // pad 1 flips it
```

旋鈕依序接 slider，推桿接在旋鈕後面，打擊墊接 toggle 和 button。轉旋鈕時 OPC 面板上的滑桿跟著動，
`parameterChanged()` 照常會被叫。OpenProcessing 的 OPC 面板自己也能學實體控制器（面板上的 MIDI 開關），
一看到它的對應在動，實體控制器就交給它，這一行繼續接螢幕上的控制器和手機（這兩個 OpenProcessing 看不到）。
OPC 變數不要取 p5 已經有的函式名稱（`hue`、`fill`），p5 1.x 會撞名。

## 麥克風

同一行也接得上麥克風，草圖讀它的方式一樣：讀變數。

```js
function draw() {
  background(230, 40, 10);
  fill(200 + bass * 160, 70, 100);                      // bass: the low end, 0..1
  circle(width / 2, height / 2, 50 + micLevel * 300);   // micLevel: how loud, 0..1
}

function beatDetected(level) {                          // like keyPressed(): a beat just landed
  // flash, spawn, jump to the next scene
}
```

| 讀 | 值 |
|---|---|
| `micLevel` | 0 到 1，現在多大聲（有平滑；安靜的房間是 0，很近很大聲是 1） |
| `bass`、`mid`、`treble` | 0 到 1，20–250 Hz、250–2000 Hz、2000–8000 Hz 三段的能量 |
| `beat` | 每個拍子有一格是 `true`，像按著滑鼠時的 `mouseIsPressed` |
| `micIsOn` | 麥克風有沒有在跑 |
| `startMic()`、`stopMic()` | 用程式開、關（回傳 promise） |

| 寫這個函式 | 什麼時候被叫 |
|---|---|
| `beatDetected(level)` | 一個拍子：音量比房間剛才的樣子突然跳起來（level 0 到 1） |
| `kickDetected(level)`、`snareDetected(level)`、`hatDetected(level)` | 低、中、高頻段各自打一下（20–120 Hz、150–800 Hz、6–14 kHz） |

**草圖開口要，它才開。** 頁面載入時什麼都不會要。草圖第一次讀到 `micLevel`、`bass`、`mid`、`treble`、`beat`，
或呼叫 `startMic()`，瀏覽器才會問你要不要給麥克風；答案回來之前，每個值都是 `0`。只寫了 `beatDetected()`、
什麼值都沒讀的草圖，會在第一次點擊或按鍵時開。🎹 面板裡的 **🎤** 按鈕可以手動開關、顯示音量；瀏覽器擋下麥克風時，
它會寫出來（從網址列左邊重新允許之後，再按一次）。

- **瀏覽器要你先點一下的話。** 瀏覽器在頁面被點過之前不讓聲音動起來。這個檔在 `draw()` 一讀到值就去要，
  瀏覽器擋住的話，第一次點擊或按鍵再開一次，所以不用寫 `userStartAudio()`。
- **跟 p5.sound 並存。** 分析用的是 [`@openav/audio`](packages.md)（一個 `AnalyserNode`），第一次用到時從這個檔旁邊載入，
  有自己的 `AudioContext`。同一頁可以放 `p5.sound`（`p5.AudioIn`、`p5.FFT`），兩邊的麥克風互不相干，這裡新增的名字
  也沒有一個跟 p5 或 p5.sound 的名字重複。p5 1.x、2.x 的全域模式都能用。
- **麥克風太小聲或太大聲。** `OAVp5.mic.gain = 3` 把 `micLevel` 和三個頻段乘三倍（上限還是 1）。
  `OAVp5.mic.on('beat', fn)` 跟定義 `beatDetected` 一樣，回傳一個可以取消的函式。
- **你自己的名字優先。** 草圖裡已經有 `bass`、`mid`（`let`、函式、別的函式庫）的話，原本的會留著，
  這個檔也不會為了它去開麥克風。
- **關掉自動開。** `?mic=click`（或 `window.OAV_P5 = { mic: 'click' }`）：只有 🎤 和 `startMic()` 能開；
  `mic=off` 就什麼都開不起來（名字還在，值一直是 0）。跟所有用麥克風的頁面一樣，要 `https` 或 `localhost`。
- 現成可開的麥克風草圖：`p5/examples/mic/`。

## 三種輸入

| 輸入 | 怎麼用 |
|---|---|
| 實體控制器 | Chrome、Edge、Firefox 的 Web MIDI，瀏覽器問一次就記住 |
| 螢幕上的控制器 | 按 🎹 打開 `<oav-controller>`，接上哪台控制器就換成哪台 |
| 手機 | 面板上的 📱 顯示 QR code，手機[遙控頁](remote.md)的 MIDI 分頁就能彈這份草圖 |

三種輸入進來都是同一串 MIDI，草圖分不出是誰彈的（想知道的話看 `midi.last.source`）。Safari 和 iPad 沒有
Web MIDI，螢幕上的控制器和手機照樣能用。草圖自己寫了 Web MIDI（`navigator.requestMIDIAccess`、WebMidi.js）的話，
螢幕和手機會變成多出來的一個輸入，名字叫 **OAV Virtual MIDI**。

## 在 Hydra 裡用

[Hydra](https://hydra.ojack.xyz) 有自己的載入函式；同一個檔在那裡也能用，Hydra 的箭頭函式每一格都會重讀變數：

```js
await loadScript('https://openaudiovisual.com/p5/oav-p5.js')
osc(10, 0.1, () => knob1 * 2).out()                     // knob 1 sets the colour offset
```

```js
osc(10, 0.1, () => 1 + micLevel * 3).out()              // the microphone, asked for when this line first runs
```

`note`、`velocity`、`knob1` … `knob8`、`fader1` …、`pad1` …，還有 🎹 螢幕上的控制器，都一樣在。
Hydra 不是 p5，沒有可以定義的 `notePressed()` 回呼，改用訂閱：
`midi.on('notePressed', (note, velocity) => { … })`（回傳一個取消訂閱的函式）。測試用的是 hydra-synth 1.4.0，
也就是編輯器跑的那個函式庫（`p5/test/hydra-smoke.cjs`）。

## 細節

- **為什麼用 `prepend`**：p5 的友善錯誤檢查會把頁面上最後一個 `<script>` 當成你的草圖。這個檔放在最前面，
  就不會被誤當成你的程式。
- **為什麼非同步載入的一行就夠**：p5 等到視窗的 `load` 事件才開始全域模式，而頁面載入中插進來的 script 會讓
  `load` 等它跑完，所以 `setup()` 裡就已經有 `knob1`。
- **這一行沒載到時**（沒網路、網址打錯），讀 `knob1` 的程式會停在「knob1 is not defined」。
- **嵌到別的網站**：OpenProcessing 自己的頁面允許草圖用 MIDI 和麥克風，它給的嵌入碼沒有。要讓嵌入的草圖聽實體控制器，
  在那個 `<iframe>` 加上 `allow="midi"`；要它聽麥克風，加 `allow="microphone"`。
- **選項、MIDI 層的寫法和測試**：[`p5/README.md`](https://github.com/frank890417/open-audiovisual/tree/main/p5)。
  範例：`p5/examples/particles/`、`p5/examples/opc/`、`p5/examples/mic/`。
