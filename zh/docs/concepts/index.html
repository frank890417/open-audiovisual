核心概念#

第 3 章，共 22 章原始檔: docs/zh/concepts.md

六個詞撐起整套框架：訊號、參數、路由、世界、時間軸、演出。這一章一個一個講清楚，最後講把它們綁在一起的兩條規則。

訊號#

訊號（signal）是一個有名字的數值，告訴你現在發生了什麼：一顆旋鈕的位置、房間裡的音量、手腕的高度、上一個和弦的協和度。每個輸入套件都把訊號發布到同一個登錄表（@openav/core 的 Signals），除此之外什麼都不做。訊號是輸入唯一的通用貨幣。

訊號有兩種：

種類存放的是範例讀取方式
連續目前的值，通常在 0..1 之間midi/cc/74 = 0.42signals.get(name)、signals.norm(name)
脈衝最近一次事件帶的內容midi/note/on → { note: 60, vel: 0.8, … }signals.on(name, cb)

名稱是路徑，來源放最前面：midi/cc/74、audio/band/low、pose/hand/right/y、phone/ab12/tilt/x、surface/main/hue。只要在演出上說得通，範圍都會正規化，y 軸也會翻過來，讓 1 代表舉高。你拿到的絕不會是原始的像素值。

宣告訊號時要帶上範圍，儀表和 learn 才知道怎麼縮放它：

js
signals.define('breath/pressure', { min: 0, max: 1, source: 'breath' });
signals.set('breath/pressure', 0.37);               // continuous
signals.define('breath/sigh', { kind: 'pulse' });
signals.pulse('breath/sigh', { depth: 0.8 });       // pulse

對一個沒人宣告過的名稱呼叫 set()，會當場把它定義成 0..1 的連續訊號。如果你的數值落在別的範圍（角度、MIDI 音高編號），請先宣告範圍。

一顆旋鈕、一隻舉起的手、一個和弦的協和度，在這個登錄表裡平起平坐。正因為這樣，你才能把它們混著用：旋鈕做得到的，手也做得到。

參數#

參數（param）是世界在聽的數值：hue、bloom、gravity。參數由世界自己宣告，每個參數是一行 schema：

js
{ key: 'energy', label: 'Energy', min: 0, max: 1, def: 0.3 }
{ key: 'mode', label: 'Mode', min: 0, max: 3, def: 0, step: 1 }   // stepped: snaps, holds on the timeline
{ key: 'burst', label: 'Burst!', pulse: true }                      // a trigger, not a level

每一格畫面，每個參數都會解析成一個數字：

text
timeline automation at time t      (the score; def if the param has no automation)
  ⬑ overridden by → the latest override   (a slider, a mapped knob, a phone fader)

覆寫會黏住（sticky）。一旦有手或路由碰過 bloom，時間軸就不再推動它，直到你清掉覆寫（在控台按 ✕，或呼叫 params.clearOverride('bloom')）。這跟舞台上一樣：人一伸手接管，樂譜就讓位。路由可以選別的做法：mode: 'trim' 把旋鈕疊加在時間軸的值上，release 讓旋鈕靜止時把參數還回去（映射）。手和路由都碰到一個參數時，最後一個刻意的改變算數，重複不算改變：再送一次同一個讀數的來源，永遠推不掉手設定的值（誰握著一個值）。params.holder(key) 和控台會說出是誰握著它。

完整的欄位列表在寫一個世界。

路由與映射#

路由（route）把一個訊號接到一個參數。路由就是單純的資料：

js
{ source: 'pose/hand/right/y', target: 'energy', curve: 'smooth', smooth: 0.15 }

映射器（mapper，@openav/mapping）收著所有路由，也負責套用：讀取訊號，夾進一個範圍（inMin..inMax），需要的話反轉，用曲線彎折，縮放到參數的範圍，有指定的話再隨時間做平滑。一個訊號可以推動好幾個參數，一個參數也可以聽好幾個訊號。learn 會綁定下一個動起來的訊號，旋鈕和揮動的手都適用。路由可以序列化成 JSON，所以一套接線就是一個檔案，可以帶到下一個場地。細節：映射。

世界#

世界（world）就是作品：一個物件，裡面有名稱、參數，以及 init、update、render、dispose。它每一格讀已解析的參數，遇到離散事件也可以直接訂閱訊號。要怎麼畫由它自己決定，2D canvas、p5、three.js、WebToe 節點網路、DOM 都可以，框架不管。細節：寫一個世界。

時間軸與場景#

時間軸（timeline，@openav/timeline）就是樂譜：每個參數的關鍵影格自動化，加上一串場景，每個場景附標題和給演奏者的備註。時間歸它管，世界從來不讀時鐘。場景可以排在 0 秒之前，當作開演前的待命。細節：演出控制。

演出#

演出（show）就是一個世界，加上呼叫一次 createShow()（@openav/show）。這一呼叫會建好訊號登錄表、參數、舞台、時間軸、映射器、你要的輸入、聲音、控台、後台資料流和畫面迴圈，然後全部回傳給你。每個範例都是一個世界加上這次呼叫，所以框架長出新模組時，每場演出只要宣告一下就能用。

js
const show = await createShow({
  world,
  timeline: { total: 120, automation, scenes },
  routes: [{ source: 'audio/rms', target: 'energy', smooth: 0.1 }],
  modules: { keys: { base: 48 }, chord: true, audio: true, sound: true },
});

兩條規則#

框架的每個部分能自由組合，靠的是這兩條規則。每條都有兩種說法，一種講系統怎麼設計，一種講寫程式的人因此要守什麼。

1. 訊號是輸入唯一的通用貨幣。所以：連續控制走參數，離散事件可以直接用訊號。

假設一個世界在 update() 裡直接讀 signals.get('midi/cc/74')，今天配上你的控制器還是能跑，但時間軸、舞者的手腕、手機或別人的控制器，就再也演奏不了它。你等於把這場演出焊死在一個輸入上。改成宣告一個參數，讓一條路由接上 midi/cc/74 → yourParam。這樣同一個世界誰都能用，控台、手機控制面板和 learn 也都看得到這個參數。

事件就不一樣了。「按下一個音」「一個和弦解決了」「大鼓打了一下」都是瞬間，不是持續的數值。在 init() 裡訂閱它們是對的，我們也鼓勵這麼做。世界能對你反應，靠的就是這些事件，少了它們，世界只會自己飄。

2. 世界永遠不知道誰在演奏它。所以：外殼永遠不知道作品是什麼。

世界讀的是參數，數值來自時間軸、MIDI 旋鈕、舞者還是推桿，它看不見。框架也一樣：不要為了讓某個範例好看去改 packages/*。改框架，就要讓每件作品都變好。換作品，就是換掉世界和它的資料，外殼留著不動。
