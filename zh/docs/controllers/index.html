MIDI 控制器與嵌入#

第 11 章，共 21 章原始檔: docs/zh/controllers.md

open-audiovisual 把 MIDI 控制器寫成資料：每台裝置一個 JSON 檔，記下面板配置、每個控制項送出的 MIDI 訊息、LED 回饋、怎麼認出它的埠，以及每個數字出自哪一份文件。同一個檔案可以變成螢幕上能彈的控制器，接上實體裝置時跟著動，也能放進任何網頁。支援的裝置全部列在控制器頁面。

放進網頁#

html
<script type="module" src="https://openaudiovisual.com/packages/midi/element.js"></script>
<oav-controller profile="akai-lpd8" readout></oav-controller>

這樣就接好了。沒有 Web MIDI 的瀏覽器（Safari、iPad）一樣能彈、一樣送出事件，只有硬體和 MIDI 輸出這兩項會顯示無法使用。沒打開 hardware、midi-out 或學習模式，它就不會跟瀏覽器要 MIDI 權限。Safari 沒有，是因為 WebKit 沒有實作（bug 107250，至今還開著）。

屬性作用
profile哪一台：id、短名稱，或你自己的設定檔 JSON 網址
layoutauto、face（照實物的樣子）或 stack（為直拿的手機重新排）
hardwareon，或 ask 顯示一個按鈕：實體裝置會帶動螢幕上那一台
midi-out埠名稱（IAC、loopMIDI）、/正規表示式/ 或 ask：彈的東西送到這個埠
channel1–16，你的機器設在別的頻道時用
picker、readout、learn、follow裝置選單、最後一則訊息、學習按鈕、接上哪台認得的裝置就切到哪台

接收它的事件#

js
const el = document.querySelector('oav-controller');
el.addEventListener('control', (e) => {
  const { id, value, signal, message, source } = e.detail;
  // 'k1'  0..1  'midi/lpd8/k1'  { type: 'cc', ch: 1, cc: 70, value: 53 }  'ui' | 'hardware'
});
await el.ready;
el.set('k1', 0.5);           // 像手一樣動一個控制項
el.ingest([0xb0, 70, 64]);   // 從任何地方來的 MIDI：面板會跟著動

其他事件：noteon、noteoff、connect、disconnect、status、profilechange、ready、 error。全部都會冒泡，也會穿過 shadow root。每個事件有哪些欄位，都寫在 packages/midi/README.md。

不用自訂元素#

js
import { createController } from 'https://openaudiovisual.com/packages/midi/index.js';

const ctl = createController('akai-lpd8', { signals });   // signals：發進一場演出
ctl.mount(document.querySelector('#pads'));                // 可省略
ctl.on('control', (e) => console.log(e.signal, e.value));

在演出裡，別在 update() 裡直接讀 midi/lpd8/k1，改用 controllerRoutes(profile, { k1: 'hue' }) 把它接到參數（AGENTS.md 的第一條規則）。範例 09 就是這樣一次接好六台裝置。

用 iframe#

給只能放 iframe 的地方：

html
<iframe src="https://openaudiovisual.com/embed/controller/?profile=akai-lpd8&readout&frame=pads"
        width="720" height="220" style="border:0" allow="midi" title="AKAI LPD8"></iframe>

每個事件都會包成 { source: 'openav', type, frame, detail } 傳給上層網頁。反過來，它也接受 { target: 'openav', type: 'set' | 'ingest' | 'press' | 'release' | 'reset' | 'profile' | 'layout' | 'get', … }。加上 origin=https://你的網站，它就只跟你的網頁對話。

用它彈你的 DAW#

  1. macOS：音訊 MIDI 設定 → 視窗 → 顯示 MIDI 工作室 → IAC 驅動程式 → 勾選「裝置已上線」。 Windows 11：內建的 Windows MIDI Services（2026-02-17 釋出，24H2、25H2 分批推送）讓各程式共用 MIDI 埠，並附有 loopback；微軟的公告寫明，用 Web MIDI 的網頁也能用（Windows 部落格）。我們沒有拿它跟 open-audiovisual 一起實測。舊版 Windows：安裝 loopMIDI，新增一個埠，這條路仍然可用。
  2. <oav-controller profile="akai-lpd8" midi-out="IAC">（Windows 上填你建立的埠名，或 Windows 顯示的埠名）。
  3. Ableton Live：把那個輸入的 Track 和 Remote 打開。TouchDesigner：放一個 MIDI In CHOP。 Resolume：到 Preferences → MIDI。

螢幕上彈的會送出去，實體硬體的動作不會轉送（DAW 本來就聽得到它）。引擎從不聽 IAC 輸入，元素也會把跟輸出同名的輸入靜音，所以不會繞成迴圈。

使用統計#

為了知道控制器和演出被用在哪裡，套件在每次載入頁面時，會送出一筆匿名紀錄到 Google Analytics 4（openaudiovisual.com 的資源，G-1YG2JHK2WT）：

事件什麼時候內容
oav_embed_load<oav-controller>、createController() 或 iframe 開始運作oav_kind（element、headless、iframe）、oav_profile、oav_host、oav_version
oav_hardware_connect接上實體控制器，而且對上了機型oav_kind、oav_profile、oav_host、oav_version
oav_show_startcreateShow() 開始oav_kind（show）、oav_host、oav_version

oav_host 只有網頁的網域（iframe 的話是放它的那個網頁），不會送路徑、查詢字串或標題。彈了什麼不會送出，也不寫 cookie，每次載入頁面的識別碼都是隨機的，沒辦法拿來追蹤同一個訪客。套件不會載入 gtag.js，網頁自己裝的 Google Analytics 不受影響。在 localhost、區域網路、file://、openaudiovisual.com 本站，或瀏覽器開了「不要追蹤」（Do Not Track、Global Privacy Control）時，什麼都不送。

關掉的方法：<oav-controller telemetry="off">、createController(p, { telemetry: false })、createShow({ telemetry: false })、iframe 加 ?telemetry=0，或在載入前設 globalThis.OPENAV_TELEMETRY = false。程式在 packages/midi/telemetry.js。

p5.js 的那一行（oav-p5）預設什麼都不送，草圖自己設 telemetry: 'on' 才會送。

簽名不是一筆紀錄。 createShow() 還會在頁面的 head 裡放一個 <meta name="generator" content="open-audiovisual 0.9.0">，WordPress 和 Hugo 留的也是這種標籤。它不發出任何請求，檢視原始碼的人、公開網頁的搜尋與普查可以從它讀出哪些頁面跑在 open-audiovisual 上，就這樣而已。createShow({ signature: false }) 就不放。原始碼：packages/core/src/signature.js。想被列出名字的作品，自己到用它做的加上來。

網站自己的頁面#

openaudiovisual.com 自己的頁面裝了 Google Analytics 4（同一個資源）。除了 Google Analytics 本身會算的瀏覽次數，assets/track.js 另外記下訪客在頁面上做的九件事，每件都是一個獨立的事件：

事件什麼時候內容
oav_copy按下「複製」，或在程式碼區塊裡按 ⌘C、Ctrl+Ckind（loader、code、import_map、other）、page_type
oav_outbound點了連到別的網站的連結kind（github、vendor、work、course、openprocessing、other）、host、page_type
oav_controller_play第一次動頁面上的螢幕控制器，每次瀏覽只記一次controller、page_type
oav_export_download從控制器、燈具或設備頁下載 QLC+、Mixxx 或 JSON 檔format（qlc、mixxx、json）、controller（控制器、燈具或設備的 id）、page_type
oav_example_start在範例裡第一次點擊或按鍵，每次瀏覽只記一次example
oav_next_step點了頁面「下一步」區塊裡的連結from（頁面類型）、to（p5、example、docs、reference 等）
oav_search在搜尋框打下第一個字，每次瀏覽只記一次page_type
oav_lang_switch按 EN 或中文page_type、to（en、zh）
oav_send_to_desktop按下手機上那一條「把這一頁傳到電腦」的按鈕method（share、copy）、page_type

page_type 是頁面的類型：home、controller、controllers_index、verify、example、examples_index、docs、docs_chapter（/docs/<章>/）、reference、reference_name（/docs/reference/<名稱>/）、cheatsheet、p5、made_with、changelog、webtoe、check、not_found、devices_index（/devices/）、fixture（/fixtures/<id>/）或 device（/devices/<id>/）。每個內容都只是一個短字或 id，不會有複製了什麼、在搜尋框打了什麼，也不會有連結的路徑或查詢字串：host 只有對方網站的名稱。跟每一次瀏覽一樣，Google Analytics 本身也會記下頁面的網址，並寫入它自己的 cookie。這支程式只在網站的分析程式有跑的地方跑，也就是 openaudiovisual.com，localhost 和複製出去的 repository 都不會。原始碼：assets/track.js。

這些都不在框架裡。p5/oav-p5.js、packages/、embed/ 不會載入這支程式，也不會多送任何東西，所以別人用 open-audiovisual 做的網頁，送出的仍然只有第一張表列的內容。tests/track.test.js 兩件事都會檢查。

SysEx：模式、模板、LED 顏色#

有些事只有 SysEx 做得到：把 Launchpad 切到程式模式、選 Launch Control XL 的模板、把打擊墊點成任何 RGB 顏色。有這些功能的設定檔會列在 sysex，每則訊息都附出處，機器的頁面看得到。

瀏覽器會為 SysEx 跳權限視窗，所以這個專案絕不自己要權限：<oav-controller sysex> 會加一顆按鈕，背後是 controller.enableSysex()（要在使用者按下時呼叫）。開啟之後，機器每次連上都會設定好，setLedColor(id, { r, g, b }) 和 sendSysex(id) 也能用。套件 README。

在其他軟體使用#

每台機器的頁面都有同一份資料的 QLC+ 輸入設定檔（.qxi）和 Mixxx mapping（.midi.xml 加一支小 .js），node tools/export-controller.mjs <id> 也能從任何設定檔產生。Mixxx 的檔案只是起點，請用 Mixxx 的 Learning Wizard 改成你要的。資料庫也列出從 QLC+ 輸入設定檔匯入的控制器，版面是自動產生的，每個控制項都標成未確認。

加入一台控制器#

  1. 從 packages/midi/profiles/ 複製最接近的檔案，或一個通用版面。
  2. 照說明書的 MIDI 實作表，寫下每個控制項的類型和訊息。
  3. 每一筆資料都寫上出處。還沒確認的，標上 "verified": false，再寫一句說明。"verified": true 只給在實機上確認過的數字，而且要在 verifications 留一筆紀錄，寫明誰、哪一天、什麼韌體、作業系統和瀏覽器（沒有的話 validateProfile 不會過）。
  4. validateProfile(profile) 會列出所有問題，npm test 會檢查每一個內建設定檔。
  5. 用 <oav-controller profile="./my-device.json"> 試彈，再登記到 profiles/index.js，開一個 pull request。

沒有說明書的話：選一個通用版面，按「學習」，把控制項一個一個動過去，再把 controller.exportMapping() 的結果存下來，當作設定檔的起點。

這個格式也放得下音符和 CC 以外的東西：sysex（切模式、換模板、LED 顏色，每則訊息都附出處）、palette（LED 色票）、verifications（誰在實機上驗過什麼）。完整欄位在套件 README，同一份格式的 JSON Schema 在 profile.schema.json。
