套件一覽#

第 19 章，共 23 章原始檔: docs/zh/packages.md

三十三個套件放在 packages/<name>/。每一個都是純 ES module，沒有任何相依套件。在網頁裡透過 import map，用 @openav/<name> 引入（照抄 examples/01-hello-particles/index.html 裡那份就好）。目前還沒有發布到 npm。

層套件
L1 輸入midi · audio · chord · pose · leap · keys · drums
L2 映射mapping · chop
L3 世界stage · world-webtoe
L4 輸出sound · osc · out · dmx · output · record · fab（MIDI 輸出在 midi 裡）
主軸timeline · score · pattern · console · monitor · sync
手機relay · surface · remote · tile
膠水core · show · devices · mcp

子路徑入口（@openav/remote/host、@openav/relay/server、@openav/surface/layout、@openav/surface/auto）在瀏覽器裡要各自在 import map 加一行，例如 "@openav/remote/host": "../../packages/remote/host.js"。

@openav/core#

膠水 · 共用的語言：Signals、Params、Loop、Bus。

匯出簽章

Loopnew Loop(onFrame(dt, now), { maxDt = 0.1, clock, raf, manual = false, heartbeat }) · start() · stop() · step(dt) → boolean（跑一個長度 dt 秒的影格，不夾上限）· fps、running、manual。clock() → 毫秒（預設 performance.now），raf(cb) → 下一格（預設 requestAnimationFrame）；注入 raf 或 manual 會關掉分頁藏起來時的 Worker 心跳（heartbeat: true 可打開）。見自己驅動影格

signals.define('breath/pressure', { min: 0, max: 1 });
signals.on('breath/pressure', (v) => console.log(v));
signals.set('breath/pressure', 0.4);

@openav/show#

膠水 · createShow(options)：呼叫一次，以一個世界為中心組好整場演出，再把每個部分交給你。選項、模組和回傳值見演出控制；loop、monitor、console（控台的 keys）決定誰來給影格、後台推送送去哪裡、哪些鍵操作控台。sync 讓這個頁面成為好幾個演同一場的頁面之一（主控端或從屬端，見 @openav/sync）。同一個頁面加上 ?output 就是乾淨的輸出：只剩黑底上的舞台，沒有控台（@openav/output）。

js
import { createShow } from '@openav/show';
const show = await createShow({ world, modules: { keys: { base: 48 }, sound: true } });

@openav/chop#

L2 映射 · 數值隨時間的變化，像 TouchDesigner 的 CHOP 那樣塑形：Lag、Trigger（這裡叫 envelope）、Speed、Spring、Trail、Slope、Count。純邏輯，沒有自己的時鐘：每一步都告訴它過了幾秒，並在那段時間裡精確求解，所以 30 fps 和 144 fps 畫出同一條曲線。參數意義參考 TouchDesigner 官方文件（Derivative），程式由 OAV 自行實作。在 p5 草圖裡，oav-p5 把它們做成一行一個：見 p5 一行注入。

匯出簽章
approachapproach(current, target, seconds, dt) → 一極點 lag 的一步；seconds＝跟上 63% 變化的時間（@openav/mapping 的 smooth 就是用它算）
Lagnew Lag({ up = 0.1, down = up }) · step(input, dt, up?, down?) → 輸出 · reset(v?)：上升用 up、下降用 down（Lag CHOP 的 Lag 1／Lag 2），秒數是 TouchDesigner 的（大約跟上 90% 變化的時間）
envelopeenvelope(times, t, attack = 0.01, decay = 0.3, peak = 1) → Trigger CHOP 在時間 t 的值（事件時間 times，秒，舊的在前）：直線上升（0 → peak），decay 秒後剛好回到 0；還沒落完又觸發，從當下的高度接著走 · envelopeStage(elapsed, attack, decay, from, peak)
Speednew Speed() · step(rate, dt) → 位置：每秒加 rate
Springnew Spring({ stiffness = 100, damping = 6 }) · step(target, dt) → 位置（另有 velocity）：掛在彈簧上的質點被拉向輸入，精確解 · springStep(x, v, target, k, c, dt) → [x, v]
Trailnew Trail({ seconds = 2, rate = 60 }) · step(value, dt) → 最近 seconds 秒，每秒 60 個值再加上最新的一個，舊的在前，長度固定
Slopenew Slope() · step(value, dt) → 每秒變化量
Countnew Count({ threshold = 0.5 }) · step(on, limit = 0) → 打開過幾次；給 limit 就在 0 … limit − 1 之間循環 · wrapCount(total, limit)
TD_LAG_RATIO、DEFAULTSMath.LN10：這裡有兩種秒數。Lag 與 lag() 收的是 TouchDesigner Lag CHOP 的秒數（大約是跟上 90% 變化的時間），所以 lag(x, 0.1) 動起來就像 Lag CHOP 設 0.1；Lag 內部再除以 TD_LAG_RATIO（2.3）換成時間常數。approach(…, seconds) 收的就是時間常數本身（跟上 63%，@openav/mapping 的 smooth 一向是這個意思）；上面那些預設值
js
import { Lag, envelope } from '@openav/chop';
const vu = new Lag({ up: 0.03, down: 0.4 });       // opens at once, closes slowly
// every frame: r = 50 + vu.step(level, dt) * 300; pump = envelope(kickTimes, now, 0.01, 0.3);

@openav/dmx#

L4 輸出（燈光）· 從網頁打 DMX，全部是純邏輯：燈具 profile（open-audiovisual/fixture@1）、把屬性（dimmer、color、pan、tilt、strobe、zoom，0..1）換成每台燈位元組的 patch，以及依時間算出每台燈任何時刻樣子的引擎：基礎 scene → 有淡入淡出的 cue → 跟著拍子的 chase → effect → 即時值 → 每台燈的上下限 → 總控 → blackout。安全機制預設開著，閃爍上限（每秒 3 次）以每台燈來算，守兩層：引擎把會讓同一台燈閃的 effect 和 chase 放慢，直到它們在這台燈上的頻率加起來不超過上限（state(t).slowed），每一個 dmxTransport() 再讓每一格經過頻閃保護，管住每台燈實際發出的光，即時值也算在內（變亮的次數有限額，變暗永遠直接通過，{ flashGuard: false } 才會關掉，監看器那時會一直顯示）。profile 寫了 Hz 的 strobe 通道遵守上限，沒寫 Hz 的停在 open。render(t, { beat }) 要連 bpm 一起給，因為上限要靠拍速計算。control 通道（重置、燈泡開關、內建程式）只有 control() 能寫。blackout 時 pan、tilt 停在原處。Art-Net、sACN 和 Enttec DMX USB Pro 的位元組由純函式編碼，dmxTransport() 每一格把有變的部分送出去（留在記憶體、經輸出橋接程式，或用 Web Serial），dmxParams() 把引擎的控制點變成參數，mountDmxMonitor() 把燈畫在頁面上。還沒有用任何一台真的燈、節點或介面試過。完整說明在 DMX 燈光 那一章。

@openav/tile#

手機 · 幾台平放在桌上的螢幕變成一張畫布：拍一張標記的照片定位每台螢幕，經過中繼共用的時鐘和一個種子讓它們一起演，每台只畫自己的那一塊。它不是 @openav/output，那是一個只算一次的舞台，透過輸出視窗送上投影機。這裡是很多台裝置各自算一張畫布裡自己的那一塊，位置由一張照片決定。它的時鐘也不是 @openav/sync：沒有主控頁面在傳播放頭，每台螢幕自己問中繼現在幾點（差別寫在那一章）。章節是多螢幕拼接：一張畫布，範例 30，拍照頁是 packages/tile/?room=<名字>（?demo=1：合成照片，不需要硬體）。

@openav/devices#

膠水 · 演出設備大集合：每一份 MIDI 控制器 profile（手寫的和轉入的）、每一台 DMX 燈具、電子零件庫的每一個零件，以及鏡頭、音訊介面、感測器、LED 與 DMX 介面、印表機的手寫紀錄，收在同一種外層紀錄裡（open-audiovisual/device@1，@openav/devices/device.schema.json），每一筆事實都有出處。沒有任何東西是複製的：每份 profile、燈具和零件都留在自己的檔案裡，紀錄從那裡讀出來（node tools/build-devices.mjs 寫出清單 catalog.js），所以列清單不會載入任何 profile。完整說明在設備那一章。
