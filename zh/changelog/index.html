0.8.0#

2026-10-16 · 9bdde95

  • 收音符號碼的地方，音名也能用。 noteIsDown('C4') 就是 noteIsDown(60)，midi.play('C#4', 0.8) 送出音符 61，新的 midi.isDown('Eb3') 用音名問一個鍵。C4、c#4、Db3、F♯2、C-1（0）到 G9（127）都行；C4 是 60 （有些軟體，像 Ableton 和 Yamaha，把 60 叫 C3）。Strudel 的小寫寫法（c4 e4 g4）也行。寫錯的音名會停下來，跳出一張卡片告訴你怎麼寫。數字的行為跟以前完全一樣，notePressed(note, velocity) 拿到的仍然是號碼。音名
  • 三個換算函式： noteNumber('C4') 得到 60，noteName(61) 得到 'C#4'（{ flats: true } 是 'Db4'， { octave: false } 是 'C#'），noteFreq('A4') 得到 440 赫茲，給自己合成聲音的草圖用。
  • 現成草圖：p5/examples/note-names/（範例 24）。

  • 像 TouchDesigner CHOP 的數值工具：lag(micLevel, 0.03, 0.4)（Lag CHOP，秒數跟 TouchDesigner 一樣：大約跟上 90% 的時間）、env('kick', 0.01, 0.3)（Trigger）、speed()、spring()、trail()、slope()、count()， draw() 裡一行一個，不用宣告；scope(值, '標籤') 在角落畫出數值的曲線（不會錄進影片），drawTrail() 畫在畫布上。新套件 @openav/chop。

  • 現成草圖：p5/examples/rhythm-visual/、p5/examples/lag/、p5/examples/with-strudel/。

框架與網站#

2026-11-25#

  • 把舞台送上投影機：0.12.0。 新的套件 @openav/output。createOutputs(show, { outputs, aspect }) 在載入時宣告演出的輸出，在點擊時呼叫 outputs.open('main') 就開出輸出視窗：黑底、沒有控台、游標兩秒後消失，按 F 全螢幕，電腦接了好幾個螢幕時還會列出每個螢幕，點哪個就在哪個全螢幕（Window Management API，只在那個視窗裡點擊時才詢問）。預設是鏡像舞台的畫布（只算一次，畫面完全一樣：量過，大小一樣，顏色一樣）。{ mode: 'page' } 則用乾淨網址把同一個頁面再開一次，跟著這個頁面的時鐘和被握住的值。投影與影像輸出
  • 四角校正，以及跟著場地走的設定。 在輸出視窗按 E 會出現四個把手：拖到螢幕的四個角（或用 1 到 4 加方向鍵），畫面就彎過去貼合，背後是一個 CSS matrix3d 單應矩陣（cornerPin()、toMatrix3d()）。H 和 V 為背投翻轉，O 轉 90°，[ ] 加黑邊，還有柔邊，按 G 顯示跟著彎的測試圖。設定依輸出名字存在瀏覽器裡，Export layout／Import layout 把它變成可以帶著走的檔案（open-audiovisual/output@1）。四角校正
  • 黑場和亮度是參數，一張畫布可以分給兩台投影機。 每個輸出都有 output/<name>/blackout 和 output/<name>/brightness，所以控台、MIDI 推桿和時間軸都推得到投影機。裁切（{ x, y, w, h }）把一個 32:9 的舞台分給兩台 16:9 的投影機（沒有邊緣融合）。一張畫布給兩台投影機
  • 每場演出都有乾淨網址。 任何 createShow() 的頁面加上 ?output，就只剩黑底上的舞台和存下來的四個角，沒有控台、鋼琴、提示和導覽卡。&follow=oav-output（跨瀏覽器再加 &via=relay）讓它跟著演出頁面，&play 讓它的時間軸開始播。這就是給 kiosk 瀏覽器、OBS 的瀏覽器來源和 TouchDesigner 的 Web Render TOP 用的網址，章節裡有三種做法和場地清單。OBS 和 TouchDesigner 的步驟是照它們的文件和安裝好的軟體自己的介面文字寫的，標成待確認：兩個軟體都還沒實際跑過，也還沒上過真的投影機。乾淨網址
  • 範例 29，投影輸出。 一個照畫布形狀畫圓環的世界、Open output window 按鈕、編輯模式和測試圖，時間軸結尾淡到黑，?pair 給兩台投影機。投影輸出
  • 用手設定的值會留著：0.11.0。 好幾個寫入者碰到同一個參數或同一個引擎的值時，現在由一條規則決定誰說了算，框架裡的每一個寫入者都照它走：最後一個刻意的改變算數，重複不算改變。手（控台的滑桿、params.override()、新的 params.hold() 和 sound.set()、✕）設定的值會一直留著，直到被放開，或有來源真的動了。再送一次同一個讀數的來源（relay 每秒替每支手機的控制項重送一次）、平滑路由的滑行，還有把 sound/* 送進聲音引擎的那一步，都不能再把它推掉。sound.update() 在值變了的時候才交給引擎，不再每個影格送每一個值（一件裝置作品在 3 秒裡數到 181 次沒變過的音量寫入），trim 也只在加總變了的時候才寫。params.holder(key) 說得出是誰握著一個參數，參數面板也會顯示：手握著的名稱是黃色加 ✋，路由握著的是藍色加 ⇄，提示文字裡有來源。誰握著一個值
  • 升級到 0.11.0。 作品可能看得出來的不同：自訂的聲音引擎（modules.sound: { engine }）在值變了的時候才收到 set(key, value)，enable() 之後和換樂器之後每個值各收一次，不再每個影格都收，所以寫進引擎的值會留到它的參數動了為止。✕、滑桿或 params.override() 之後，路由要等來源改變超過輸入窗的 0.1% 才再接管參數，再送一次同一個讀數不會再把它拿回去。手握著參數的時候才加進來的路由（學來的、匯入的、載入的），從第二個讀數起才接管。別人的任何寫入都會讓滑行停下，寫的是它正經過的那個數字也一樣。沒有手介入的時候，每個影格的值都跟以前一樣。一件作品如果靠著舊的做法，會是這幾種：引擎的 set() 必須每個影格都跑，✕ 之後指望手機、OSC 或 relay 的重送把參數放回去，或者程式在開場覆寫了一個參數，指望路由的第一個讀數把它換掉。一行就能原封不動找回 0.10.0，會印出「已不建議使用」的警告：createShow({ writes: 'legacy' })（或在 new Mapper() 和 new Sound() 上寫 writes: 'legacy'）。沒有任何名稱被拿掉或改名。新的有：params.hold()、params.holder()、sound.set()、sound.release() 和 writes 選項。0.10.0 的規則
  • 修正，來自 2026-11-15 的一次審查。 new Timeline({ anchor: 0 })（epoch 是 0 毫秒）被當成沒有錨定。SyncLeader 的 cut 函式丟出錯誤時，每個影格剩下的部分（段落模組、映射器、舞台）都停了，現在那一幀照樣送出、不帶 cut，錯誤只記一次。SyncLeader.status().followers 只會變多，所以重新載入的從屬頁面會被算兩次：從屬端現在每 2 秒說一聲還在（aliveEvery），close() 時說再見，主控端 6 秒沒聽到就把它忘掉（forgetAfter）。0.10.0 的從屬端兩樣都不說，照以前那樣算。
  • 在手機上：把這一頁傳到電腦，先找控制器。 首頁、/zh/p5/、範例頁、/zh/controllers/ 和每台控制器的頁面，在窄的觸控螢幕上會出現一小條「把這一頁傳到電腦」：按下去會打開手機的分享選單，沒有分享選單就複製連結，按 × 這次瀏覽就不再出現，按下時記成 oav_send_to_desktop（share 或 copy）。/zh/controllers/ 最上面是搜尋框和廠牌篩選，涵蓋每一台控制器的頁面，在手機上，控制器面板要捲到螢幕附近才畫（HTML 不變）。螢幕上的控制器本來就能用手指彈（pointer 事件），這次用觸控螢幕確認過。
