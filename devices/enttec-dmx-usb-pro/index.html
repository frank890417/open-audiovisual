Try it

The frame ENTTEC DMX USB Pro receives

Three DMX channels as sliders, written into one universe and wrapped in the Pro’s “send DMX” message (label 6) by encodeEnttecDmx(), the bytes Web Serial or the out-bridge would write to the port. Nothing is sent.

0x7E start · 0x06 label · length · start code 0 · channels · 0xE7 end

Setup

Set it up

  1. From a page with no bridge: dmxTransport('serial', { patch, universe: 1 }) and a Connect button that calls connect(); the browser asks which port only from a click. Chrome or Edge on a computer, on https or localhost. open-audiovisual handbook: DMX lighting (Web Serial and the enttec sink, safety, not here)
  2. Through the out-bridge instead: an enttec route with the serial device's path, { "match": "dmx/1/*", "sink": "enttec", "path": "/dev/cu.usbserial-…", "universe": 1 }. A missing device is a status, retried every 2 s. open-audiovisual handbook: DMX lighting (Web Serial and the enttec sink, safety, not here)

Known problems

  • On Web Serial there is no watchdog: the Pro keeps repeating the last frame, so send a blackout before close(). open-audiovisual handbook: DMX lighting (Web Serial and the enttec sink, safety, not here)
  • OAV writes the Pro's "send DMX" frames but no RDM; and an Enttec Open DMX or a bare FTDI cable is not this device and does not work with it. open-audiovisual handbook: DMX lighting (Web Serial and the enttec sink, safety, not here)

Use it

ENTTEC DMX USB Pro in your code

Paste it into a <script type="module"> on any page: it loads the packages from this site. It asks for nothing until you press the button it adds.

javascript
import { device } from 'https://openaudiovisual.com/packages/devices/index.js';
import { Patch, DmxEngine, dmxTransport } from 'https://openaudiovisual.com/packages/dmx/index.js';

const pro = await device('enttec-dmx-usb-pro');   // ENTTEC DMX USB Pro
console.log(pro.record.protocols.join(' '));
// → dmx512 rdm enttec-usb-pro
const patch = new Patch();
patch.add({ id: 'par1', profile: 'generic-rgbw', mode: '6ch', address: 1 });
const engine = new DmxEngine(patch);
engine.set('par1', { dimmer: 1, color: [1, 0.5, 0] });
const out = dmxTransport('serial', { patch, universe: 1 });
const button = document.body.appendChild(Object.assign(document.createElement('button'), { textContent: "Connect the ENTTEC DMX USB Pro" }));
button.onclick = async () => { await out.connect(); out.send(engine.render(0)); };   // the browser asks which port

What reaches it

  • @openav/dmx · dmxTransport

    const out = dmxTransport('serial', { patch, universe: 1 }); button.onclick = () => out.connect()

    The page writes whole Enttec frames by Web Serial, at most one every 25 ms while anything changes and once a second otherwise, through the flash guard.

  • @openav/out · OutClient · sink enttec

    dmxTransport('bridge', { patch, client: new OutClient({ url: 'ws://127.0.0.1:6450/out' }).connect() })

    The out-bridge's enttec sink carries one universe to the Pro on a serial device, with the watchdog's safe values when the page goes away.
