Use it

Generic Moving head (RGBW) in your code

Paste it into a <script type="module"> on any page: it loads @openav/devices and @openav/dmx from this site, patches the light at address 1 in mode 16ch and prints the bytes it would send. Send them with dmxTransport() (Art-Net or sACN through the out-bridge, or an Enttec DMX USB Pro by Web Serial).

javascript
import { device } from 'https://openaudiovisual.com/packages/devices/index.js';
import { Patch, DmxEngine } from 'https://openaudiovisual.com/packages/dmx/index.js';

const light = await device('generic-moving-head');   // Generic Moving head (RGBW)
const patch = new Patch();
light.patch(patch, { id: 'light1', address: 1, mode: '16ch' });   // 16 channels from address 1
const engine = new DmxEngine(patch);
engine.set('light1', { dimmer: 1, color: [1, 0.5, 0], pan: 0.5, tilt: 0.25 });
console.log(engine.render(0).bytes(1).slice(0, 16).join(' '));
// → 128 0 64 0 0 255 0 255 128 0 0 0 0 0 0 0

It prints the channels of mode 16ch, in order:

  1. pan 128
  2. panFine 0
  3. tilt 64
  4. tiltFine 0
  5. speed 0
  6. dimmer 255
  7. strobe 0
  8. red 255
  9. green 128
  10. blue 0
  11. white 0
  12. gobo 0
  13. zoom 0
  14. focus 0
  15. program 0
  16. reset 0

Where it comes from

Sources, licence, verified

Written by hand for OAV as a common channel order. No single fixture is behind it.

Licence: MIT. Nobody has checked this file on a light for this project yet: every value is as the source says it.

Sources

  • open-audiovisual generic layout No single fixture behind it: a common channel order, written by hand. Read the manual of your light and, where its order or ranges differ, copy this file and change it before patching a real fixture. The strobe ranges say open and strobe but no Hz: a generic file cannot know how fast a given value flashes, so under the 3 Hz cap the engine keeps this channel open. Pan and tilt start at the middle (128). Which value of reset moves the head back home, and what the built-in programs do, differs from fixture to fixture: program and reset are control channels, written only by an explicit call (a built-in program flashes as it likes, outside the cap).
