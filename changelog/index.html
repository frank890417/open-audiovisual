Written in Markdown in docs/changelog.md; this page is generated from it. GitHub ↗

What changed, newest first: what you can do now, and where the handbook explains it. oav-p5, the one line for p5.js sketches (p5.js in one line), has its own version: 🎹 → 🩺 shows it on any sketch that loads it. 0.8.2#

2026-10-20 · b0ebbd7

  • A hit as a value, like mouseIsPressed. kickIsDetected, snareIsDetected and hatIsDetected are true in the one frame after a kick, a snare or a hat (the drum machine's, or the microphone's when no drums play). lag() takes true as 1, so lag(kickIsDetected, 0, 0.3) is a number that flashes to 1 and fades: an alpha, a size. kickIsDetected
  • When the last one came. lastKickTs, lastSnareTs, lastHatTs, lastBeatTs and lastNoteTs are on the millis() clock, so millis() - lastKickTs is how many ms ago; -Infinity until the first. lastKickTs

0.8.1#

2026-10-20 · 096914f

  • The 🎹 panel goes where you want it. Two buttons on the panel: Dock cycles bottom → top → floating (drag a floating panel by its bar), Size cycles small → medium → large. This browser remembers both. With no dock option the panel now opens at the bottom, OpenProcessing included: at the top it covered the sketch. The 🎹 moves out of the panel's way only when they share an edge. dock
  • A reload brings back what you had on. Cmd+Enter on OpenProcessing (or any reload of the same page) opens the panel again if it was open, and restarts drums you started from its 🥁 on the line and tempo you ended on. A sketch that starts its own drums keeps its own; close the panel or stop the drums and they stay off.
  • With the drums playing, a kick is one kick. The microphone's kick, snare, hat and beat no longer reach the sketch while the drum machine plays: it mostly heard the drums out of the speakers, so snareDetected fired on kicks. micLevel and the three bands still follow the microphone. kickDetected
  • OpenProcessing's console stays shut. It opens over the sketch for every console line, so there oav-p5 no longer prints what it says on its own (the wiring, a hint that is on a card, "sound on"). An error in your code, a call made wrong and 🩺 still print; debug brings the rest back.

  • A value set by hand stays set: 0.11.0. One rule now decides who wins when several writers touch one param or one engine value, and every writer in the framework follows it: the last deliberate change wins, and a repetition is not a change. A hand (the console's slider, params.override(), the new params.hold() and sound.set(), ✕) holds the value until it is released or a source really moves. A source that sends the same reading again (the relay refreshes every phone control once a second), a smoothed route's glide and the push of sound/* into the sound engine can no longer undo it. sound.update() hands the engine a value when it changed, not every value every frame (an installation counted 181 writes of an unchanged volume in 3 seconds), and a trim writes only when its sum moves. params.holder(key) says who holds a param, and so does the Params panel: a name held by a hand is yellow with ✋, one held by a route blue with ⇄, the source in its tooltip. Who holds a value
  • Upgrading to 0.11.0. What a work can see differently: a custom sound engine (modules.sound: { engine }) gets set(key, value) when a value changes, and every value once after enable() and after an instrument change, instead of every frame, so a value written into the engine stays until its param moves. After ✕, a slider or params.override(), a route takes its param again only when its source changes by more than 0.1% of its window: the same reading sent again no longer takes it back. A route added while a hand holds its param (learned, imported, loaded) takes it from its second reading on. A glide stops for any other write, the very number it is passing included. Without a hand in the way the values are the same as before, frame for frame. A work leaned on the old way if its engine's set() has to run every frame, if it counts on a phone, OSC or relay re-send to put a param back after ✕, or if its code overrides a param at start and expects a route's first reading to replace that. One line brings 0.10.0 back exactly, with a deprecation warning: createShow({ writes: 'legacy' }) (or writes: 'legacy' on new Mapper() and new Sound()). Nothing was removed or renamed. New: params.hold(), params.holder(), sound.set(), sound.release() and the writes option. The 0.10.0 rule

  • No light flashes more than 3 times a second. The cap is held per fixture, in two layers. The engine slows the effects and chases that flash one light until they add up to 3 Hz there (state(t).slowed says which). Every dmxTransport() then puts each frame through a flash guard that holds what each fixture really emits, live values included: a kick drum on a dimmer at 180 bpm sixteenths, 12 flashes a second, leaves as 3. Blackout is never held back. Switching the guard off takes { flashGuard: false }, and the monitor then shows FLASH GUARD OFF. Safety
  • Three DMX sinks in the out-bridge. artnet (unicast to the node by default, as Art-Net 4 asks), sacn (multicast or unicast, a priority, "stream terminated" on a clean stop) and enttec (an Enttec DMX USB Pro on a serial device): 40 frames a second while values change, a keep-alive each second, safe values when the page goes away ("hold" keeps a moving head where it points). Each holds every channel to 3 flashes a second, on by default; "flashGuard": false or an exempt list on the route for a head's pan and tilt, which a per-channel guard would otherwise make step.
